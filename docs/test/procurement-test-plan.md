## 1. 概述与目标

- **测试对象**：采购与资产管理系统（政府/事业单位内部 Web 系统）全功能点 **U0–U14**——预算 → 科目对照 → 两级审批 → 采购执行/验收入库 → 领用/审批出库 → 盘点，及工作台聚合与轻量 RBAC。
- **测试目标**：验证功能符合 PRD 与各功能点详设；关键业务主线闭环可用；权限边界、状态机、库存防超发/超收、预算导入校验等关键约束正确；达到上线质量门槛。
- **质量目标（可量化）**：
  - 冒烟用例 **100%** 通过方可进入功能测试；
  - 功能用例执行率 **100%**、通过率 **≥ 98%**；
  - 遗留缺陷 **0 个 P0/P1**（致命/严重）；
  - 关键不变量零破坏：库存 `quantity ≥ 0` 且 `== Σ stock_txn.qty_change`、出库零超发、入库零超收、审批节点-角色不可越权。

## 3. 测试类型与策略

| 测试类型 | 是否做 | 策略/说明 |
|---|---|---|
| 冒烟测试 | ✅ | 每次提测先跑 `smoke-test.md`，关键主线不通直接打回 |
| 功能测试 | ✅ | 按 `test-case.md` 全量执行，黑盒/验收视角 |
| 接口测试 | ✅ | 对照各详设 §6 接口契约，校验入参/出参/错误码（40001/40301/40401/40903/40904/42201-42205/50000） |
| 集成测试 | ✅ | 跨页/跨模块主线闭环（导入→比对→审批；采购→入库；领用→出库；盘点账实校正） |
| 兼容性测试 | ☐（按需） | Chrome/Edge 最新版优先；分辨率 ≥1366 宽（原型固定 Semi 主题） |
| 性能测试 | ☐（按需） | 列表 P99<300ms、库存流水百万级分页（详设 U10 §7 T-11，本轮抽样不压测） |
| 安全测试 | ✅（轻量） | 越权（各 `@SaCheckRole`）、未登录拦截、口令不回显（SysUserVO 不含 password_hash）、目录穿越（到货单下载）；衔接 `/security-review` |
| 回归测试 | ✅ | 缺陷修复后回归 + 关键用例回归；已含开发侧集成测试（后端 14 类、前端 18 文件）作为白盒回归底座 |
| 验收测试 | ✅ | 对照 PRD 成功标准，业务方确认主线可演示（里程碑 M5） |

> **与开发单测分工**：开发侧已落 `*IntegrationTest`（真实 PostgreSQL，覆盖事务/行锁/并发/对账等白盒约束）与前端 Vitest（组件/纯函数）；本测试方案为黑盒/验收视角，走界面与接口，覆盖业务场景与交互呈现，二者互补不重复。

## 7. 准入 / 准出标准

- **准入（开始测试）**：代码通过 `tkxm-review`（已跑 `/code-review`，5 项收口于 `005f344`）；部署成功；内置角色/基线数据就绪；冒烟用例 100% 通过；本用例集已评审。
- **准出（结束测试 / 可上线）**：
  - 全量用例执行完毕，通过率 ≥ 98%；
  - 无 P0/P1 遗留缺陷；中低（P2/P3）缺陷有结论与跟踪；
  - 关键不变量用例（防超发/超收、账实一致、节点-角色、口令不回显）全部通过；
  - 验收测试通过，业务方签字；
  - PRD 成功标准达成。

## 8. 缺陷管理

- **严重度**：P0 致命（阻断主流程 / 数据丢失 / 库存为负或超发 / 越权可写） · P1 严重（核心功能不可用 / 错误码不符契约） · P2 一般（边界/容错/交互瑕疵） · P3 轻微（文案/极端组合）。
- **流程**：提报 → 研发确认 → 修复 → 回归 → 关闭；争议升级测试负责人。
- **缺陷指标**：缺陷密度、修复时长、回归通过率。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 盘点期间库存不冻结（U12 §5.2/TBD-2）：快照后并发出入库，gain/loss 流水 `type` 可与 `qty_change` 符号不一致 | 审计口径困惑（非数据错误，INV-3 仍成立） | 用例标注为「已知设计」；推动产品定是否冻结范围；账实一致仍以确认时实值为准 |
| 「已发生」口径取采购下单额而非入库实收（U13 TBD-1） | 验收口径分歧 | 用例按下单口径判定；如改实收口径回溯 `tkxm-detail` |
| 库存聚合粒度（material+project_group，DB TBD-1） | 同名跨批次合并展示 | 用例按现聚合键判定；如引入批次/序列号回溯设计 |
| 测试时间被压缩 | 覆盖不足 | 优先 P0/P1 与冒烟；P2/P3 视余量 |
| 无 Docker 环境 | 部分集成/性能用例阻塞 | 本地 PG 即可跑功能；性能用例标注环境依赖 |
