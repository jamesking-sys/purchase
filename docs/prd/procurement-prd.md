# PRD：采购项目管理系统

> 状态：已确认 · 创建日期：2026-06-04（2026-06-05 按新模板重构） · 负责人：<待确认>
> 上游：阶段一需求文档 `docs/requirement/procurement-requirement.md` · 下游：`tkxm-prototype`（原型图）
> 设计风格：**Semi Design**（与前端脚手架 Semi UI 一致；原型支持运行时切换其它风格预览）

## 1. 背景与问题

- **当前痛点 / 用户问题**：项目采购从「立项预算」到「资产入库、领用、盘点」的全过程缺少统一系统支撑——预算与科目割裂、审批靠线下、采购与库存数据不连续，一笔采购事后难以追溯来龙去脉，多项目并行时尤甚。
- **为什么现在做**：把「预算 → 科目 → 两级审批 → 采购执行 → 验收入库 → 领用/出库 → 盘点」做成一条**可追溯的闭环**，支撑多项目并行，并为后续资产折旧、预算变更台账留好扩展位。
- **业务目标**：交付覆盖上述全链路的多项目采购管理系统，全流程状态可追溯（量化成功基线见 §7 TBD-1）。

## 2. 范围

### 2.1 本期要做（In Scope）
- 多项目下的：预算模板导入、预算科目划分与管理（多级树/模糊搜索）、科目比对与人工新增、两级审批（驳回退回重提）、采购执行、到货单上传、多次到货验收入库、库存生成、领用申请、仓管审批出库、定期盘点与差异调整。
- 轻量 RBAC（角色 + 部门/项目组数据归属）。
- 预算与实际支出**仅展示对比，不做余额核减/管控**。

### 2.2 本期不实现、但预留接口（Reserved for Future）
> 本期不落地，但需在架构/接口层预留扩展点，确保后续接入无需大规模重构。
- **物料消耗与资产折旧**：库存/资产记录预留生命周期状态与价值/原值字段位；首个实现接入「领用消耗登记」与「折旧计提」时不改库存主流程。
- **预算变更与台账输出**：预算与科目模型预留版本/变更记录维度；预算余额核减预留计算接入点（本期仅展示对比）。首个实现为「预算变更单 + 台账导出」。
- **可配置审批流**：审批单本期已**泛化为多业务类型**（`biz_type`+`biz_id`），固定两节点（采购主管 → 部门主管）；预留流程编码与节点顺序，后续接入「审批流程定义」即可按业务类型灵活配置，无需重建模型。

### 2.3 明确不做（Non-goals）
- 立项文档自动解析抽取预算（仅模板导入 + 附件留档）。
- 完整供应商主数据 / 合同管理模块（仅可选轻量字段）。
- 细粒度组织树与字段级授权。
- 预算占用/可用余额实时核减与超预算拦截。
- 审批流的**可配置编排**（本期审批单虽支持多业务类型，但流程固定两节点，可配置编排留待后续）。

## 3. 目标用户与场景

主要用户角色（多项目 + 轻量角色；部门、项目组为数据归属维度）：

| 角色 | 职责 |
|---|---|
| 编制人（项目组/采购员） | 导入/录入预算、划分科目、提交审批；发起采购执行、上传到货单；发起领用 |
| 采购主管 | 审批节点一：审核预算与科目划分 |
| 部门主管 | 审批节点二：终审预算与科目划分 |
| 仓管员 | 验收入库；核库存并审批出库；执行盘点与差异调整 |
| 领用人（项目组成员） | 发起物料/资产领用申请 |
| 系统管理员 | 维护部门、项目组、用户与角色分配 |

典型用户故事：
- 作为**编制人**，我希望用模板导入项目预算并逐级拆到科目，以便快速生成可审批的预算科目结构。
- 作为**采购主管/部门主管**，我希望在系统里审批预算科目并能驳回退回，以便留痕且可追溯。
- 作为**仓管员**，我希望验收到货后入库、并对领用核库存后审批出库，以便库存账实可控。
- 作为**项目组成员**，我希望发起领用申请并跟踪出库状态，以便及时拿到物料。

## 4. 用户流程 / 交互

主线流程：
```
导入预算（模板）/ 上传立项文档留档
   → 逐级划分预算科目（多级树，默认 5 级）
   → 与库中科目比对 → 缺失科目人工新增确认
   → 提交审批：采购主管 → 部门主管（驳回则退回修改重提）
   → 审批通过，进入执行
   → 采购执行（可填供应商/合同）→ 上传到货单
   → 多次到货验收入库 → 生成/累加库存
   → 项目组发起领用 → 仓管员核库存并审批出库 → 扣减库存
   → 定期盘点 → 记录盘盈/盘亏差异 → 确认后调整库存
```
关键状态与边界：
- **空状态**：无预算/无科目/无库存/无待办时给出引导。
- **加载/校验**：导入大文件、提交审批、出库扣减需有加载与结果反馈。
- **错误/边界**：导入格式错误定位到行；金额只允许叶子级；出库库存不足拦截；驳回必须填意见；并发出库避免超发。
- **状态机（采购单/预算）**：编制中 → 采购主管待审 →（驳回 ↩ 编制中）部门主管待审 →（驳回 ↩ 编制中）已通过 → 执行中 → 已入库。

## 5. 功能需求

> 逐条可独立验证，带优先级 P0/P1/P2。按功能域分组。

### 5.A 基础与权限
- **[P0] A1 组织与归属维护**：维护部门、项目组（项目组归属某部门）、用户。
  - 验收标准：可创建/编辑部门、项目组、用户；项目组必须挂在一个部门下；资产/物料、预算等业务数据均携带项目组与部门归属。
- **[P0] A2 角色与登录**：登录认证 + 按角色（编制人/采购主管/部门主管/仓管员/领用人/管理员）控制可见与可操作功能。
  - 验收标准：无权限角色不可进入对应操作入口；同一用户可被赋予多个角色；越权操作被拒绝。

### 5.B 预算与科目
- **[P0] B1 预算模板导入**：提供 Excel/CSV 预算模板，导入后生成预算明细行；支持上传立项/预算文档作附件留档。
  - 验收标准：能下载模板；导入校验格式与必填列，错误行给出可定位的错误提示；导入成功生成对应预算明细；附件可上传与下载。
- **[P0] B2 预算科目划分（多级树）**：按预算逐级划分科目，科目为多级树形结构，**默认 5 级、可在末级向下继续扩展**，预算/金额挂在叶子级。
  - 验收标准：可在任意非叶子节点下新增子级（含超过 5 级）；金额只能录在叶子级；父级金额为子级汇总；树可展开/折叠。
- **[P0] B3 科目管理与模糊搜索**：科目的查询、维护，支持名称/编码模糊搜索。
  - 验收标准：输入关键字可模糊匹配科目名称或编码并高亮定位；搜索结果可在树中跳转。
- **[P0] B4 科目比对与人工新增**：将划分出的科目与库中现有预算科目对照，对缺失科目提供「新增科目」选项，由人工确认后入库。
  - 验收标准：比对结果清晰标出「已存在/缺失」；缺失项可一键发起新增，经人工确认后写入科目库；未确认不写入。

### 5.C 审批
- **[P0] C1 两级审批**：预算与科目确认后提交审批，依次经 采购主管 → 部门主管两个串行节点。审批模型**泛化支持多业务类型**（以业务类型 + 业务单据 id 关联），本期实例为预算科目审批、固定两节点。
  - 验收标准：提交后进入「采购主管待审」；通过后进入「部门主管待审」；两级均通过则状态变为「已通过/可执行」；每步记录审批人、时间、意见；审批单可承载不同业务类型而无需改表结构。
- **[P0] C2 驳回退回重提**：任一审批节点可驳回，驳回则退回编制状态，编制人修改后重新提交、重走审批。
  - 验收标准：驳回须填写意见；驳回后单据回到「编制中」且可编辑；重新提交从采购主管节点重新开始；驳回意见与历次流转可查。
- **[P1] C3 审批待办与历史**：各审批人有待办列表；任意单据可查看完整审批流转历史。
  - 验收标准：待办仅显示该角色待处理项；历史按时间顺序展示全部节点动作。

### 5.D 采购执行与入库
- **[P0] D1 采购执行**：审批通过后进入执行；记录采购执行结果，可选填供应商名称、合同号等轻量字段。
  - 验收标准：仅「已通过」单据可进入执行；供应商/合同为可选字段，不填不阻断；执行记录与预算科目关联。
- **[P0] D2 到货单上传**：采购执行支持上传到货单（附件）。
  - 验收标准：可上传一个或多个到货单文件并下载；记录上传人与时间。
- **[P0] D3 验收入库**：验收到货后入库，生成库存记录，携带项目组/部门归属。**支持多次到货分批入库**：一个采购单可有多张入库单，采购明细按累计已收数量核对。
  - 验收标准：入库需关联采购执行项；入库后生成/累加对应物料库存；同一采购单可多次入库，累计已收不超过采购数量；库存记录可追溯到来源采购单与到货单。
- **[P1] D4 预算 vs 实际对比展示**：在采购执行/科目视图展示预算金额与实际支出对比（仅展示，不核减）。
  - 验收标准：按科目展示预算、已发生金额、差额；不对超出做任何拦截或扣减。

### 5.E 领用与出库
- **[P0] E1 领用申请**：项目组成员发起物料/资产领用申请。
  - 验收标准：可选择库存物料、填写数量与用途，提交后进入「待仓管审批」。
- **[P0] E2 仓管核库存并审批出库**：仓管员核对库存后审批出库，出库扣减库存。
  - 验收标准：审批时校验可用库存；通过则出库并扣减对应库存数量；库存不足时给出提示且不可超发；驳回须填意见。
- **[P1] E3 领用/出库记录追溯**：领用与出库形成可追溯记录（申请人、审批人、物料、数量、时间）。
  - 验收标准：任一出库可回溯到领用申请与库存来源。

### 5.F 盘点
- **[P0] F1 定期盘点**：发起盘点任务，按部门/项目组列出在册资产/物料供盘点。
  - 验收标准：可按部门/项目组生成盘点清单；记录账面数量供录入实盘数量。
- **[P0] F2 盘点差异与库存调整**：盘点生成盘盈/盘亏差异明细，确认后据实调整库存并留盘点记录。
  - 验收标准：系统自动计算账实差异；差异经确认后调整库存到实盘数；盘点单与调整记录可查。

## 6. 验收标准 / 完成定义（DoD）

- 全部 P0 功能需求通过其验收标准。
- 一个采购单可端到端走完「预算/科目 → 两级审批 → 采购执行 → 到货上传 → 验收入库 → 领用 → 仓管审批出库」，状态全程可追溯。
- 多次到货可分批入库且累计已收不超过采购数量。
- 盘点可生成差异并据实调整库存。
- 轻量 RBAC 生效：越权操作被拒绝。
- 库存扣减零超发、入库不超收。
- 预留扩展点（折旧/预算变更/可配置审批流）在数据模型/接口层已留位，但本期不提供功能入口。

## 7. 风险与未决事项

- 风险及缓解：
  - 预算模板列定义不统一 → 提供标准模板与导入校验，错误行可定位。
  - 多项目并发出库超发 → 出库审批时校验可用库存并加并发控制（行锁 + 非负约束）。
  - 科目树超深影响可用性 → 默认 5 级、超出仅在需要时使用，UI 支持搜索定位。
- 待确认 (TBD)：

| 编号 | 待确认项 | 现状/暂定 | 决策人 |
|---|---|---|---|
| TBD-1 | 成功指标量化基线（耗时、账实一致率等） | 暂定先采集基线再定目标 | 产品/业务 |
| TBD-2 | 预算模板的具体列定义 | 暂定：科目路径、名称、编码、金额、备注 | 业务/财务 |
| TBD-3 | 物料/资产区分口径（是否按金额阈值或类别） | 暂定统一为「库存物料」，资产标识为可选属性 | 业务 |
| TBD-4 | 附件存储与大小限制 | 暂定本地/对象存储，单文件上限待定 | 技术 |
| TBD-5 | 盘点周期与触发方式（手动发起 vs 定时） | 暂定手动发起盘点任务 | 业务 |

> 阶段一遗留的 5 个需求级 TBD 已全部定稿并落入本 PRD（多级树科目、驳回退回重提、供应商可选字段、仓管审批出库、预算仅展示不核减）；本表为阶段二新识别的实现级待确认项。

## 8. 里程碑（可选）
